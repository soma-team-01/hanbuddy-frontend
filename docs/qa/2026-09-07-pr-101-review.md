# PR #101 리뷰 대응 브라우저 확인

- 날짜: 2026-09-07
- 환경: 로컬 Next.js 개발 서버, Codex 내장 브라우저
- 대상: 실제 `BookingForm`, `ApplicationList`, `RefundPolicyNotice`, `RefundPolicyDialog`
- 방법: 임시 개발 전용 페이지에서 가상 활동·결제 대기 신청 데이터와 실제 번역 정책 문서를 전달해 렌더링. 검증 후 임시 페이지 제거.
- 범위: UI 검증이며 로그인·실제 신청 생성·PG 결제 승인에 대한 E2E 검증은 아님. 결제 실행 버튼은 누르지 않음.

## 반응형 확인

| 언어   | 화면 폭(px)             | 예약 폼·환불 안내                   | 결제 대기 안내                           | 정책 전문 팝업                                   |
| ------ | ----------------------- | ----------------------------------- | ---------------------------------------- | ------------------------------------------------ |
| 한국어 | 390 / 768 / 1024 / 1440 | 가로 넘침 없음                      | 취소·결제 계속 버튼 화면 내 표시         | 제목·닫기 버튼 표시, 본문 내부 스크롤            |
| 영어   | 390 / 768 / 1024 / 1440 | 긴 제목·문구 줄바꿈, 가로 넘침 없음 | 긴 결제 버튼 문구 줄바꿈, 가로 넘침 없음 | 긴 제목 줄바꿈, 닫기 버튼 표시, 본문 내부 스크롤 |

화면 높이는 900px로 확인했다. 390px·768px는 결제 액션 바가 고정되고, 1024px·1440px에서는 본문 2열과 sticky 요약 패널이 적용된다. 모바일은 세로 스크롤로 전체 내용을 확인하며 모든 내용을 한 화면에 축소하지 않는다.

## 동작·접근성 확인

- 예약 인원·특별 요청·필수 동의를 바꾼 뒤 전문 팝업을 열고 닫아도 상태 유지.
- 전문 팝업 진입 시 닫기 버튼에 포커스, Tab 이동 시 상위 팝업 내부에 포커스 유지.
- Escape 또는 브라우저 뒤로가기로 전문 팝업을 닫으면 전문 보기 버튼으로 포커스 복귀.
- 결제 대기 안내 안에서 전문 팝업을 열고 뒤로가기를 누르면 결제 대기 안내가 그대로 유지됨.
- 결제 대기 안내에 재동의 체크박스가 없고, 취소 및 결제 계속 버튼이 표시됨.
- 한국어 Toss 경로와 영어 PayPal 경로의 결제 대기 안내 확인. 실제 결제는 실행하지 않음.

## 자동 회귀 검사

- 별도 backdrop 버튼 클릭 및 본문 클릭 구분, Escape 닫기.
- 포인터 클릭이 트리거를 포커스하지 않은 경우에도 닫은 뒤 포커스 복귀·스크롤 잠금 해제.
- 5개 언어 모두 최초 신청 동의를 유지하고 재동의를 요구하지 않는 정책 문구.
- 관리자 목록의 일반·초기 버디 수수료와 VAT 세부 표시.

## 보류 항목

결제일 고정 청약철회 기산일 지적은 사용자 결정에 따라 문구를 유지했다. 법적 적합성이나 PG 심사 충족을 확인한 것으로 취급하지 않으며, 해당 리뷰는 해결 처리하지 않는다.

## 재리뷰 후 추가 확인

임시 페이지가 아닌 실제 로그인 화면과 정책 라우트에서 확인했다. 로그인 제출·회원 생성·결제는 실행하지 않았다.

| 시나리오                                                                               | 실제 확인 결과                                                                                            |
| -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 로그인 → 이용약관 팝업, 영어·한국어 각각 390 / 768 / 1024 / 1440px                     | 정책 다이얼로그 가로 넘침 없음, 본문 세로 스크롤 가능, 최초 포커스가 팝업 내부 뒤로가기 버튼에 위치       |
| 한국어 로그인 이메일 입력 → 이용약관 → 본문의 환불 정책 링크 → 브라우저 뒤로가기 두 번 | URL이 환불 정책 → 이용약관 → `/ko/login` 순으로 복귀. 복귀 화면 캡처에서 테스트 이메일이 남아 있음을 확인 |
| 위 로그인 화면에서 앞으로가기 → 정책 화면의 뒤로가기 버튼                              | 이용약관 팝업 재표시 후 로그인 화면으로 복귀                                                              |
| 영어 이용약관 팝업에서 Tab → Escape                                                    | Tab 이동 후 포커스가 팝업 내부에 있고, Escape 후 `/en/login`으로 복귀                                     |
| 영어 이용약관 URL 직접 방문 → 새로고침                                                 | 두 경우 모두 같은 정책 URL과 영어 제목 유지, 팝업이 아닌 독립 페이지 표시                                 |
| 홈 모바일 메뉴, 영어·한국어 각각 390px                                                 | 열기 → Tab 후 메뉴 내부 포커스, Escape 후 메뉴 닫힘 및 메뉴 열기 버튼으로 포커스 복귀                     |

화면 높이는 900px이다. 한국어 모바일 로그인 복귀 화면과 영어 데스크톱 정책 화면을 브라우저 캡처로 확인했다. 캡처는 작업 세션에서만 확인했으며 저장소에 이미지 파일로 첨부하지 않았다. 내장 브라우저의 데스크톱 캡처는 표시 패널 폭으로 잘릴 수 있어 가로 넘침 판정은 실제 viewport의 DOM 치수를 함께 사용했다.

### 아직 완료하지 않은 전체 QA 범위

위 결과를 전체 서비스 반응형·인증 E2E 통과로 간주하지 않는다. 다음은 별도로 확인해야 하며, 전체 페이지군 QA를 요구한 재리뷰는 미해결 상태로 유지한다.

- 홈·탐색 카드 그리드·상세·가입·프로필·수정·버디 대시보드·활동 목록/생성/신청자·결제 결과 화면의 영어/한국어 4개 폭 전체 매트릭스.
- 인증된 실제 예약 신청 및 결제 재개, 버디 활동 등록 등 주요 업무 흐름. 앞선 예약·결제 대기 결과는 실제 컴포넌트에 가상 데이터를 전달한 UI 검증이다.
- 모든 입력 화면에서 정책 URL 연속 이동 및 히스토리 왕복, 파일 입력 보존, 스크린샷 파일 첨부.
- 모바일 메뉴의 768px 검증과 모든 포커스 순환 경계. 위 추가 검증은 390px의 Tab 이동·Escape·포커스 복귀만 확인했다.

### 재리뷰 번역 회귀 검사

일본어 버디 운영약관의 회사 요청 권한, 번체 동의 안내의 제한 사유 표기, 간체·번체 개인정보 처리방침의 공지 방법 및 기존 30일/7일 안내 기간을 자동 검사한다. 전체 검증은 `format:check`, `lint`, `typecheck`, 175개 파일의 1,309개 테스트, production build를 통과했다.
