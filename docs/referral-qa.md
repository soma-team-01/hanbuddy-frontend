# 제휴 활동 연동 확인 — #176

## 범위

HanBuddy에서는 신청·취소·개인정보 제공 동의·신청 건수만 관리한다. 실제 서비스 요금과 예약은 업체 상담 후 별도로 확정한다. 건당 수수료 계산, 청구, 정산, 외부 예약 완료 상태는 이번 구현에 포함하지 않는다.

## 실제 서버 확인 전 준비

- 백엔드 `feat/#193-referral-activity-applications`와 V60이 적용된 로컬 DB를 준비한다. 운영 DB를 테스트에 사용하지 않는다.
- 프론트의 `HANBUDDY_API_BASE_URL`을 해당 로컬 백엔드에 연결한다.
- 관리자, 활성 버디 A/B, 여행자 계정을 준비한다. 버디 B는 타 업체 접근 차단 확인용이다.
- 등록할 회차는 한국 시간 기준 시작까지 24시간 이상 남기고 정원을 작게 설정한다.
- 이 문서의 `/ko`는 한국어 경로다. 여행자 화면은 `/en`, `/ja`, `/zh-Hans`, `/zh-Hant`로도 확인한다. 버디·관리자는 기존 한국어 운영 화면을 따른다.

## 확인할 화면과 동작

| 순서 | 화면                                            | 확인할 내용                                                                                                                                                                                                                                                                                                                                                              |
| ---- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1    | `/admin/referrals` → 등록 링크 만들기 버튼      | 팝업에서 검색어 하나로 닉네임·이름·이메일을 통합 검색하고 중복 없는 결과에서 업체를 선택한다. 결과가 많으면 더 보기를 사용한다. 선택한 업체와 유효 기간으로 링크를 발급하고 즉시 복사한다. 새로고침하면 원문 링크는 재조회되지 않아야 한다.                                                                                                                              |
| 2    | 발급 링크 `/ko/referral/create#code=…`          | 로그아웃 상태에서 열고 해당 버디로 로그인한다. 복귀 후 등록 폼이 열리고 주소에서 코드가 제거되는지 확인한다. 다른 버디·만료·회수·사용 완료 링크는 등록을 막아야 한다.                                                                                                                                                                                                    |
| 3    | 업체 활동 등록 및 `/ko/my-activities/{id}/edit` | 사진 3장 이상, 설명, 장소, 일정·정원, 일정표, 포함 사항을 입력한다. 가격·할인 입력 단계가 없어야 한다. 등록 즉시 공개되며 수정에는 새 등록 링크가 필요하지 않다. 저장 응답이 불확실하면 먼저 내 활동과 관리자 발급 내역을 확인한다.                                                                                                                                      |
| 4    | `/ko/activities/{id}` → 신청하기                | 0원/무료 상품으로 표시하지 않고 업체 상담 후 요금 확정을 안내한다. 신청 화면에서 회차·인원과 제공받는 업체·항목·목적을 확인한다. 동의 전 신청 버튼은 비활성, 동의 후에는 PG 없이 확정된다.                                                                                                                                                                               |
| 5    | `/ko/applications`                              | 제휴 신청의 일정·인원·상태가 보이고 가격 상세·결제 버튼·환불 금액은 보이지 않아야 한다. 취소 후 좌석이 반환되는지 확인한다. 같은 회차 재신청은 신규 성공으로 표시하지 않아야 한다.                                                                                                                                                                                       |
| 6    | `/ko/my-activities` → 제휴 신청 내역            | 버디 A에게 자기 활동 신청만 보이는지 확인한다. 이름·연락처·회차·인원은 신청 당시 정보다. 버디 B로 같은 정보를 조회할 수 없어야 한다.                                                                                                                                                                                                                                     |
| 7    | `/admin/referrals` → 활동 선택                  | 첫 화면에는 활동 목록만 보인다. 활동을 선택하면 누적 총 신청·확정·종료·취소 건수가 표시되고, 아래 내역을 일정·신청 상태·신청일 범위로 조회한다. 누적 건수는 상세 조회 필터와 별개이며 총 신청은 취소를 포함한다. 날짜 필터는 활동 시작일이 아닌 신청 생성일(KST)이다. 숫자는 참여 인원이 아닌 신청 건수다. 기본 상태는 신청 확정이며 전체를 선택하면 취소 건도 포함한다. |
| 8    | 버디 대시보드·신청자·채팅 화면                  | 제휴 회차를 취소하면 신청 취소·좌석 처리·취소 배지가 반영되는지 확인한다. 자동 환불 안내를 표시하지 않아야 하며 기존 단체 채팅방은 유지되어야 한다.                                                                                                                                                                                                                      |

### 오류·회귀 확인

- 만석·24시간 마감·시간 중복·비공개 활동은 서버 오류를 안내하고 신청을 성공 처리하지 않는다.
- 최신 동의 버전이 달라지면 안내를 새로 조회하고 체크를 다시 받아야 한다.
- 빠르게 두 번 눌러도 발급·신청·취소가 중복 요청되지 않아야 한다.
- 취소 후 같은 회차 신청 응답이 `CANCELLED`이면 확정 화면을 표시하지 않는다.
- 일반 `STANDARD` 활동은 기존 등록·가격·결제·취소·환불 흐름을 그대로 유지한다.
- 초대 코드가 API query/path, 분석 이벤트, 오류 로그에 포함되지 않는지 확인한다. 검증/등록에 필요한 POST body로만 전달한다.
- 여행자 UI 문구는 5개 언어를 지원한다. `referral-notice`의 서비스 안내·제공 항목·목적은 동의 계약을 보존하기 위해 서버가 반환한 원문 그대로 표시한다.

## 이번 작업에서 확인한 범위

- 포맷, ESLint, TypeScript, 전체 단위/계약 테스트, 프로덕션 빌드.
- 격리 샘플 API + Chrome에서 한·영 활동 상세/신청/내 신청의 390/768/1024/1440px 가로 넘침 검사.
- 샘플 API에 실제 BFF를 연결해 신청·취소, 관리자 업체 검색·링크 발급, 업체 링크 진입·코드 제거·신청 내역 화면 확인.
- 샘플 요청 기록에서 결제/환불 API 미호출 및 코드 query 미노출 확인.

실행 중인 로컬 백엔드의 OpenAPI에서 업체 검색과 신청 조회 조건을 확인했다. OAuth 로그인 왕복, DB/V60, 실제 좌석·채팅·권한 연동은 아직 미검증이다. 로컬 인계 문서는 이 검증이 끝날 때까지 보관한다.
